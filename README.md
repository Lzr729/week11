# Week 11：第九、十家公司扩展性验证

本成果包将两家新增公司的实验统一归入 Week 11：

- 第九家公司：绿联科技（301606），用于扩展性验证；
- 第十家公司：拉普拉斯（688726），用于边界实验。

## 核心结论

| 项目 | 绿联科技 | 拉普拉斯 |
|---|---:|---:|
| 标准表复用 | 9/9 | 9/9 |
| 研究变量完成 | 32/32 | 32/32 |
| 验收检查 | 17/17 PASS | 17/17 PASS |
| 强制建立 Schema v1.1 | 否 | 否 |

两家公司均可使用 Week 8 Schema v1.0、9 张标准表和 Week 9 的32个变量。Week 8、Week 9和Week 10冻结成果没有被修改。

拉普拉斯存在早期观察窗缺口，因此31个变量只能解释为2020-2022年可核验观察窗结果或下限，不能表述为完整融资生命周期。

## 精简后的目录

本包只有四个一级文件夹，不再出现“文件夹里面继续套文件夹”的情况：

```text
README.md
CHECKSUMS.sha256
data/
metadata/
reports/
scripts/
```

### data

- 两家新增公司的独立标准数据JSON；
- 十家公司整合数据JSON；
- 十家公司9张标准表CSV；
- 十家公司320条公司-变量记录；
- 两家公司合并验收结果、复用性判断和结论摘要。

为避免重复，已经删除两家公司各自重复导出的9张CSV。独立公司明细保留在公司级JSON中，GitHub分析直接使用十家公司合并CSV即可。

### reports

- 绿联科技审阅工作簿；
- 拉普拉斯审阅工作簿；
- Week 11两家公司合并评估PDF。

### metadata

- 两家公司合并来源清单；
- 发布清单和版本说明。

### scripts

- `verify_release.py`：快速检查目录、公司数量、变量数量、验收结果、旧周次残留和文件校验值。

## GitHub提交方式

解压ZIP后，将 `README.md`、`CHECKSUMS.sha256` 和四个一级文件夹直接拖入GitHub仓库即可。由于没有二级文件夹，不需要逐层进入目录上传。

## 研究边界

十家公司仍不足以支持统计显著性、回归、因果推断或行业总体代表性。现有成果主要用于样本内描述、融资结构比较、案例分析和可追溯的数据核验。
